# Zaliv — центр управления TikTok Ads

Одна админка для сотен логинов TikTok Ads: аккаунты, вход по логину и паролю (код из почты вводите вы) или по сессии (cookies),
сводка по всем рекламным кабинетам, кампаниям, расходу и причинам недоставки. Для ручных шагов (капча, подтверждения, любые действия
в кабинете) есть «удалённый браузер» прямо в панели.

Домен: **https://zaliv.vibecods.xyz** · Папка на сервере: `D:\server-projects\zaliv.vibecods.xyz` · Контейнер: `zaliv-app`.

## Что уже работает

| Раздел | Возможности |
|---|---|
| **Аккаунты** | список с фильтрами и тегами, клиент/заметки, прокси на аккаунт, массовые действия, массовый импорт `login:password` |
| **Вход по паролю** | серверный Chromium открывает страницу входа TikTok Ads, вводит логин/пароль, ждёт код из почты (вы вводите его в панели), ловит ошибки пароля |
| **Вход по сессии** | вставляете cookies (JSON из EditThisCookie/Cookie-Editor, `cookies.txt`, `storageState`, строка `Cookie:`) → проверка → синхронизация |
| **Удалённый браузер** | снимок страницы в панели + клики/ввод с вашей стороны: капча, нестандартные шаги, ручная работа в кабинете с сохранённой сессией |
| **Рекламные кабинеты** | все кабинеты и Business Center каждого логина, статус доставки, расход за 7 дней по валютам, причины («нет средств», «модерация», «бюджет»…), кампании, CSV |
| **Автосинхронизация** | раз в N минут (15–1440) обновляет активные логины, продлевает cookies |
| **Безопасность** | пароли и cookies в БД зашифрованы (AES-256-GCM, ключ `APP_KEY`), вход в панель с CSRF-защитой, лимит попыток, роли owner/admin/viewer, журнал действий |

Задел под следующие модули (создание BC/РК, шеринг, платёжные портфели, апелляции, Pixel/S2S, массовое управление кампаниями, алерты
в Telegram) описан на странице «Возможности» в панели; контракты собраны в архиве расширения TTAds Hub 1.5.0 (в репозиторий он не входит — внутренние материалы).

## Первый запуск

1. Откройте https://zaliv.vibecods.xyz и войдите под `admin` с одноразовым паролем, выданным при развёртывании. Панель сразу попросит сменить пароль.
   Потеряли пароль — на сервере: `docker exec zaliv-app node scripts/admin.js reset admin` (выдаст новый одноразовый).
2. «Аккаунты» → «Добавить». Для входа по паролю: логин (e-mail TikTok for Business) и пароль → «Войти». Когда TikTok пришлёт код на почту,
   в строке аккаунта появится кнопка «Ввести код». Если TikTok покажет капчу — «Открыть браузер» и пройдите её, вход завершится сам.
3. После входа панель сама сохранит сессию и запустит синхронизацию: в «Рекламных кабинетах» появятся кабинеты, кампании и расход.

> **Важно.** Вход в живой TikTok из серверного браузера ещё не проверен на реальном аккаунте (разведка и тесты шли на локальной имитации
> TikTok). Первый реальный вход — это проверка; что именно показал TikTok, видно в «Удалённом браузере». Подробности и находки —
> `docs/TIKTOK-NOTES.md`.

## Как устроено

```
браузер оператора ──https──> Caddy (server-caddy) ──> zaliv-app :3000
                                                     ├─ Fastify API + статическая SPA (web/)
                                                     ├─ SQLite (named volume zaliv_data, WAL, ежедневный бэкап в ./backups)
                                                     ├─ Chromium (Playwright): вход, проверка сессий, синхронизация, удалённый браузер
                                                     └─ планировщик автосинхронизации
```

- `src/` — сервер: `app.js` (хуки безопасности), `routes/`, `services/` (аккаунты, кабинеты, журнал, пользователи), `browser/`
  (`pool` — Chromium и слоты, `login-flow` — автомат входа, `operations` — вход/проверка/синхронизация, `interactive` — удалённый браузер,
  `page-scripts` — код, исполняемый внутри страницы TikTok), `lib/` (шифрование, cookies, прокси, модель кампаний).
- `web/` — SPA без сборки (ES-модули). Контракт API — `docs/API.md`.
- Данные TikTok читаются «как расширение»: `fetch` внутри страницы `ads.tiktok.com` с cookies аккаунта.

## Обслуживание (PowerShell на сервере)

```powershell
cd D:\server-projects\zaliv.vibecods.xyz
docker compose up -d --build            # обновить после изменения кода
docker logs -f zaliv-app                # логи
docker exec zaliv-app npm test          # тесты внутри контейнера (в т.ч. Chromium против имитации TikTok)
docker exec zaliv-app node scripts/admin.js reset admin   # новый одноразовый пароль владельца
docker exec zaliv-app node scripts/admin.js list          # пользователи панели
```

- Резервные копии БД: `D:\server-projects\zaliv.vibecods.xyz\backups\zaliv-YYYYMMDDHHMM.db` (раз в сутки, хранится 14 штук). Копии зашифрованных
  полей бесполезны без `APP_KEY` из `.env` — **сохраните `.env` отдельно**.
- Caddy: блок `zaliv.vibecods.xyz` в `D:\server-projects\reverse-proxy\Caddyfile` проксирует на `host.docker.internal:8120`
  (резервная копия до правки: `Caddyfile.backup-zaliv-<дата>`). После правки: `docker exec server-caddy caddy validate --config /etc/caddy/Caddyfile`
  и `docker exec server-caddy caddy reload --config /etc/caddy/Caddyfile`.
- Параметры — в `.env` (см. `.env.example`): лимиты браузеров, часовой пояс/язык браузера, автосинхронизация, `BROWSER_HEADLESS`.

## Ограничения и следующие шаги

- Реальный вход и «сессионные» вызовы нужно подтвердить первым живым аккаунтом; при необходимости усиливаем маскировку (прокси на аккаунт,
  headful под Xvfb, отпечаток на аккаунт) — план в `docs/TIKTOK-NOTES.md`.
- SOCKS5 с логином/паролем Chromium не поддерживает — используйте HTTP(S)-прокси.
- Статистика сейчас — кампании за 7 дней по каждому кабинету (как в «Обзоре» расширения); история (`ad_account_history`) копится в БД для будущих графиков.
- Мутации (включить/выключить, бюджет, создание BC/РК, шеринг, платежи) — следующий этап: контракты уже собраны в архиве расширения (`docs/internal-api-catalog.json` внутри архива).
